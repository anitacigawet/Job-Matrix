# NotebookLM API — Reference Notes

Implementation notes for Job Matrix's NotebookLM bridge. Origin: this wrapper was originally developed for Z-SPAN (a civic-meeting streaming project) and ported here mostly verbatim — the underlying NotebookLM mechanics are the same, only the consumer changes.

## Library

```python
from notebooklm import NotebookLMClient, ChatGoal, ChatResponseLength
```

The pip package is **`notebooklm-py`** (NOT `notebooklm` — that's a different project). The import name remains `notebooklm`.

- PyPI: https://pypi.org/project/notebooklm-py/
- GitHub: https://github.com/teng-lin/notebooklm-py

```bash
pip install notebooklm-py
# Optional: browser-based login support
pip install "notebooklm-py[browser]"
playwright install chromium
```

This is an **unofficial** Python wrapper. NotebookLM has no official public API; the library reverse-engineers the web app's session cookies. Be conservative with rate limits.

## Authentication

Auth uses session cookies generated by a one-time CLI login on the user's machine:

```bash
notebooklm login   # opens browser, saves cookies to local storage
```

After that, the client loads them automatically via `NotebookLMClient.from_storage()`. The cookies have a finite lifetime — when they expire the wrapper raises `ValueError("Authentication expired or invalid")` and the UI must prompt the user to re-authenticate. `server/notebooklm/auth_check.py` handles the health-check and re-login spawning.

For Job Matrix, which runs as a long-lived dev/dev-server process, the pattern is:

```python
from server.notebooklm.client import BriefingsClient

client = BriefingsClient()
await client.open()
try:
    # one or many calls
    answer = await client.query(notebook_id, "Write the daily briefing")
finally:
    await client.close()
```

## Core operations

### Create a notebook
```python
nb_id = await client.create_notebook("Daily Briefing 2026-05-16")
```

### Add a source
```python
await client.add_url_source(nb_id, "https://...", wait=True)
```
For Job Matrix's use case, the "source" might be a generated JSON or markdown blob describing the day's job-search state — uploaded as a file rather than a URL. We'll figure out the right shape when we build the briefing service.

### Configure a custom prompt + ask
```python
await client.configure_prompt(nb_id, prompt_text)
answer = await client.query(nb_id, "Generate the briefing.")
```

### Generate a Studio Audio Overview (Deep Dive — two-host podcast)
```python
result = await client.generate_audio_overview(
    notebook_id=nb_id,
    instructions="Coach me through today's job search.",
    audio_format="DEEP_DIVE",   # DEEP_DIVE | BRIEF | CRITIQUE | DEBATE
    audio_length="DEFAULT",     # SHORT | DEFAULT | LONG
    output_path="data/audio/today.mp4",
)
# result = { task_id, status, is_complete, downloaded_path }
```

Equivalents: `generate_video_overview`, `generate_infographic`.

## Open questions for Job Matrix

These were unknowns when Z-SPAN integrated; we'll re-validate as we wire this in:

1. **How best to represent "today's job search context" as a NotebookLM source.** Options: JSON blob describing tracked jobs / scores / status; a generated markdown briefing-doc; a file export of the dashboard. The right shape probably depends on how NotebookLM ingests sources — likely needs to be human-readable narrative-form for best results.
2. **Persistence of `chat.configure()`.** Z-SPAN observed it persists across queries — re-validate.
3. **Cost / quota.** NotebookLM is currently free with a Google account but Studio outputs have per-account generation quotas, which land on the user's own Google account — surface that transparently so it's never a surprise.

## Rate limit safety

- Default cooldown between API calls: 8 s (`NOTEBOOKLM_COOLDOWN`)
- Generation timeouts: audio 25 min, video 30 min, infographic 10 min
- Never increase concurrency. Never disable the cooldown. The unofficial API has invisible safety triggers we don't want to find.
