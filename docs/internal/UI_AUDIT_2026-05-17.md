# UI / IA Audit — 2026-05-17

Code-based discoverability + information-architecture audit of every page in `client/src/pages/`. Triggered by the operator's intuition that "things are scattered" — see the per-provider Test Connection button vs the theme toggle as the canonical example.

This audit identifies **issues only** — fixes are queued as chunks in [`TASKS.md`](TASKS.md). The chunks reference back here by section.

Companion doc: the operator did their own visual stream-of-consciousness pass after this audit landed; their observations largely overlapped with these findings (no separate doc was needed).

## Three confirmed bugs masquerading as IA issues

These aren't UX nits — they're broken or half-finished features. Verified by grep:

1. **Search Presets cannot be applied.** [SearchPresets.tsx](../../client/src/pages/SearchPresets.tsx) exposes `new-preset`, `edit-preset-{id}`, `delete-preset-{id}`, `toggle-preset-default` — but no `apply-preset` / `run-preset` / `activate-preset` action exists anywhere. Users can create presets that do nothing.
2. **Platforms page is orphaned.** [Platforms.tsx](../../client/src/pages/Platforms.tsx) at `/home` is the only place to toggle which job boards are enabled. The only links to `/home` in the whole codebase are the route definition in [App.tsx:86](../../client/src/App.tsx) and a back-to-dashboard button inside Platforms itself. You can only reach it by typing the URL.
3. **Onboarding hardcodes DeepSeek.** [Onboarding.tsx:354-361](../../client/src/pages/Onboarding.tsx) says "DeepSeek key not set" / "Save your DeepSeek API key in Settings" regardless of which provider is active. CLAUDE.md mandates Gemini as the default.

## Section B — Cross-cutting themes

1. **Orphaned & under-linked pages.** Platforms (`/home`) has zero entry points; Settings/Debug only from Landing or conditional banners. → Persistent top-level nav that includes Settings + Platforms.
2. **Scraper concerns split across two pages.** Per-platform on/off lives on Platforms; per-platform health telemetry lives on Settings. One user concern, two screens. → Merge.
3. **Instrumentation buttons at random depths.** Theme toggle in header, "Test Connection" 3 levels deep, "Test active provider" on the LLM card. → Consistent instrumentation strip per card.
4. **Redundant or conflicting subsystems.** Applied: Timeline + Quick Notes both rendered. Briefings: auto-poll + manual refresh. Dashboard: WorkflowArrow + button-level badges. → Pick one, retire the other.
5. **Cross-page action coupling is implicit.** Auto-scan uses "the default preset" but Settings has no preset selector and the dashboard's Scan button doesn't name which preset it'll run. Salary filter lives in two places. → Surface the active preset on the Scan button; "used by" footers on settings cards.
6. **Page header layouts diverge.** Five different patterns across 11 pages. → One shared `<PageHeader>` component.

## Section D — Limitations of this audit

This audit is **code-based, not visual**. The following classes of issue would need actual rendering to catch and are explicitly out of scope here:

- Spacing, font scale, contrast, animation timing, density.
- Focus order / a11y (tab order, focus-ring visibility, screen-reader announcement quality).
- Whether the dashboard's nav pills wrap to 2 lines on common viewports, whether the AI Debug Console pushes the eligible list below the fold, whether Settings sub-tabs collide on narrow widths.
- Whether the new theme toggle actually flips `glass-card` + gradient utilities cleanly in light mode.
- Mobile-responsive reflow at specific widths (inferred only from Tailwind `sm:`/`md:`/`lg:` classes).
